
BUYONIC
Backend API Documentation
For Angular Frontend Integration

Base URL: http://localhost:5181/api
Framework: ASP.NET Core 9  |  Auth: JWT Bearer  |  DB: SQL Server
 
1. Project Overview
Buyonic is a multi-role e-commerce REST API built with ASP.NET Core 9. It follows a 3-layer architecture: Data Access Layer (DAL), Business Logic Layer (BLL), and Presentation Layer (API). The API serves three user roles: Customer, Seller, and Admin, each with different levels of access.

1.1 Architecture
•	DAL — Entity Framework Core, SQL Server, Repository Pattern, Unit of Work
•	BLL — Managers, DTOs, Mappers, Email Service
•	API — ASP.NET Core Controllers, JWT Authentication, Swagger

1.2 Authentication
All protected endpoints require a JWT Bearer token in the Authorization header:
Authorization: Bearer <token>
Tokens are obtained from POST /api/auth/login. The token contains: userId (nameid), email, given_name, family_name, role, exp.

1.3 Roles
•	Customer — can browse products, manage cart/wishlist, place orders, submit reviews
•	Seller — can manage their products and update order statuses
•	Admin — full access to all resources, user management, category/payment management

1.4 Response Conventions
•	200 OK — successful GET / action
•	201 Created — successful POST with new resource
•	204 No Content — successful PUT / DELETE with no body
•	400 Bad Request — validation failure or business logic error
•	401 Unauthorized — missing or invalid token
•	403 Forbidden — authenticated but insufficient role
•	404 Not Found — resource does not exist

1.5 JWT Token Structure (Decoded)
nameid: string          // ApplicationUser.Id (int as string)
email: string           // user's email
given_name: string      // firstName
family_name: string     // lastName
role: string            // 'Customer' | 'Seller' | 'Admin'
exp: number             // expiry Unix timestamp (60 min default)
 
2. Auth Controller
Base route: /api/auth — All endpoints are public (no authentication required).

2.1 Register
POST	/api/auth/register
Auth	Public
Description	Register a new Customer or Seller account.
Request Body	{   "firstName": "string",       // required   "lastName": "string",        // required   "email": "string",           // required, valid email   "password": "string",        // required   "confirmPassword": "string", // required, must match password   "accountType": "string",     // required: "Customer" or "Seller"   "storeName": "string?",      // required if Seller   "address": "string?"         // optional for Customer }
Response	200 OK: "Registration successful." 400 Bad Request: array of IdentityError objects

2.2 Login
POST	/api/auth/login
Auth	Public
Description	Authenticate and receive a JWT token. Store the token client-side and attach to all subsequent requests.
Request Body	{   "email": "string",    // required   "password": "string"  // required }
Response	200 OK: { "token": "eyJhbGci..." } 401 Unauthorized: "Invalid email or password."

2.3 Forgot Password
POST	/api/auth/forgot-password
Auth	Public
Description	Send a password reset email. Always returns 200 regardless of whether the email exists (security best practice). The email contains a reset link with ?email=...&token=... query parameters.
Request Body	"user@email.com"   // plain string body, not JSON object
Response	200 OK: "If this email is registered, a reset link has been sent."

2.4 Reset Password
POST	/api/auth/reset-password
Auth	Public
Description	Reset user password using the token received by email. Extract email and token from the reset link URL query parameters.
Request Body	{   "email": "string",           // required   "token": "string",           // required, from email link (URL-decoded automatically)   "newPassword": "string",     // required   "confirmPassword": "string"  // required, must match newPassword }
Response	200 OK: "Password reset successful." 400 Bad Request: "Invalid or expired token."
 
3. Customer Controller
Base route: /api/customer — Requires authentication. Most actions restricted to Admin or Customer role.

3.1 Get All Customers
GET	/api/customer?includeOrders=false
Auth	Admin only
Description	Get all customers. Pass includeOrders=true to include each customer's orders and order items.
Request Body	None
Response	200 OK: CustomerDTO[] or CustomerWithOrdersDTO[]

3.2 Get Customer By ID
GET	/api/customer/{id}
Auth	Admin, Customer
Description	Get a single customer by their Customer.Id (not ApplicationUser.Id).
Request Body	None
Response	200 OK: CustomerDTO 404 Not Found

3.3 Search Customer By Email
GET	/api/customer/search?email=user@mail.com
Auth	Admin only
Description	Find a customer by email address.
Request Body	None
Response	200 OK: CustomerDTO 404 Not Found

3.4 Update Customer
PUT	/api/customer/update
Auth	Admin, Customer
Description	Update customer profile information.
Request Body	{   "id": number,   "firstName": "string",   "lastName": "string",   "email": "string",   "address": "string?",   "joinedAt": "datetime?",   "isActive": boolean }
Response	200 OK: "Customer Updated Successfully" 400 Bad Request: error message

3.5 Delete Customer
DELETE	/api/customer/delete/{id}
Auth	Admin only
Description	Soft-deletes the customer's ApplicationUser account (sets isDeleted=true) and removes the Customer record.
Request Body	None
Response	200 OK: "Customer Successfully Deleted" 400 Bad Request: error message

14. Angular Integration Notes

14.1 Environment
environment.ts: { apiUrl: 'http://localhost:5181/api' }

14.2 JWT Interceptor
Attach token automatically to every HTTP request:
headers: { Authorization: `Bearer ${token}` }

14.3 Token Decoding
Use jwt-decode to extract role and user info:
npm install jwt-decode
import { jwtDecode } from 'jwt-decode';
const decoded = jwtDecode<DecodedToken>(token);
// decoded.role => 'Customer' | 'Seller' | 'Admin'

14.4 Route Guards
•	authGuard — check if token exists, redirect to /auth/login if not
•	roleGuard — check decoded token role against route data.role

14.5 Important Notes
•	Cart endpoints use query params, not request body — use HttpParams
•	Order status update uses query param: ?status=Delivered
•	Wishlist and Review endpoints extract customerId from token server-side — do not send customerId from Angular for these
•	Forgot-password sends a plain string body, not a JSON object — set Content-Type: application/json and stringify the email
•	Reset password token comes URL-encoded in the reset link — pass it as-is, server decodes it
•	CORS is enabled for http://localhost:4200
